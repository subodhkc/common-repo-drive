## 2. Minor P11.1 future polish — do NOT obstruct P12

- **R11A — public link semantics:** `report-explanation-packet.ts` emits public verification link for any representative with a `publicVerificationId` (including potentially a revoked public id), whereas its MCP tool description claims only genuinely PUBLIC. Revoked public IDs intentionally resolve as REVOKED. Align description/field note to “publicly resolvable, including revoked status when applicable,” or restrict PUBLIC only if product policy demands. This is wording/contract inconsistency, not verified public data leakage.
- **R11B — completeness and interpretation:** executive `verificationItems` count is selected=0 and truncated=true when underlying items exist; `sectionsOmitted` doesn't explicitly enumerate depth-skipped items. Document `depth-filtered` vs unavailable so an agent doesn't say no technical items exist. Snapshot timestamp comes from Agent Audit and can be null when Agent Audit missing; label unestablished rather than fill with current time.
- **R11C — payload limit:** existing MCP transport rejects JSON >160,000 chars; receipt/nextActions and explanation arrays have no dedicated global packet size budget. No live oversized case reproduced; add a cheap oversized fixture later if P13 cleanup touches agent output. Preserve existing narrow read tools.

## 4. P12 source-confirmed truth gaps — priority

**P12-G01 (P1 false totals from record limits):** `app/api/v1/inventory/costs/route.ts::calculateCostsFromSDK` uses `request_logs.findMany(take:50)`, then sums ONLY those rows as “Total Cost”; admin branch `provider_cost_snapshots.findMany(take:50)` also sums bounded rows. `app/api/v1/inventory/usage/timeseries/route.ts` uses oldest 50 request logs over period then renders those as complete trend. `app/api/v1/inventory/usage/route.ts` admin fallback uses `take:100`, then totals limited results. Correct aggregates through canonical DB aggregate/groupBy/query or report explicitly bounded/partial; **never call 50/100 fetched rows complete financial totals or full trend**. Pagination can remain for item browsing. Use Decimal arithmetic where supported and document exact cents/rates/currency.

**P12-G02 (P1 source/metric confusion):** `usage/route.ts` provider-admin fallback sets `totalCalls = adminCosts.length`, increments `byProvider.calls` for each **cost snapshot**, synthesizes “request logs” with statusCode=200, tokens=0 and latency=0 despite those metrics not being observed. Source admin billing snapshots != calls; unknown token/latency/status must be NULL/NOT_RECORDED (not zero/healthy). Page must not display apparent call rate, token totals, green status, synthetic request outcomes from snapshots.

**P12-G03 (P2 selected-organization drift):** `usage/timeseries/route.ts` derives org from `session.user.organizationId` directly, unlike summary and costs using `requireOrganizationAccess(req,session)`. In organization-switching contexts, trend could refer to the session default while summary refers to selected organization, making misleading same-page comparison. Require the same canonical authorized org resolver and fail closed for unauthorized requested org; add delayed-request org switch guard on client.

**P12-G04 (P2 source-of-truth selection):** `costs/route.ts` picks SDK dataset whenever `sdkIntegrated`, else admin dataset; this is not a reconciled provider billing total. Avoid merging overlapping SDK estimated costs and provider billed amounts; show two lanes or explicit source selector and data completeness. No “real-time provider billing” claim from an SDK record.
 
**P12-G05 (P2 price provenance):** `lib/ai-inventory/usage-tracking/pricing.ts` carries manually coded pricing marked January 2026. Provider rates vary by model/date/region/cache/batch; distinguish caller-supplied estimated cost, fixed-rate estimate and actual provider billed snapshot. Avoid live pricing claims unless version/current rate verified; no new external API integration required.

**P12-G06 (P2 empty/stale/status honesty):** `usage/page.tsx` says “Comprehensive tracking” and “No Usage Data Yet” on zero records without source completeness; cost page shows 0.00 derived from absent `summary` fields. Show `Not connected / Configured no signal / Partial / Snapshot received / Read unavailable`, timestamps and coverage. A record source observed 0 ≠ no spending; sample counts ≠ total usage. Charts follow a source-qualified data window, not decorative zeros.

**P12-G07 (scope and integrity):** `usage/log/route.ts` now verifies supplied `aiSystemId` belongs to authenticated organization before inserting `request_logs` (the old PX1.2 Phase 0 audit marked this P0, but **CURRENT SOURCE FIXED**; do not reopen the stale issue). API-key read/writer scope, body validity, cost-source provenance, rate-limit/cursor/origin and org/system identity still merit targeted testing before any broader ingestion change. Don't log or expose provider keys/prompts.

**P12-G08 (read/MCP parity):** Provider usage/cost may be informative to authorized connected agents, but don't invent a `haiec_get_usage_cost` tool unless actually registered. First inspect existing MCP guide/tool registry; provide a read-only, scoped tool or explicit “not available through MCP” only after source owner review, using same metric semantics and permissions as UI. Avoid conflating provider usage and HAIEC billing.
