No credentials, session cookies, or org override in copied text.

- `haiec_list_evaluations`, `haiec_get_summary`, `haiec_get_master_report`, `haiec_get_agent_audit`: exact frozen Evaluation/report reads. `haiec_get_agent_audit` attaches deterministic `resolutionGroups` using `lib/mcp/guided-assurance.ts`, including `verificationNeeded`, `affectedQuestionIds`, `affectedPathIds`, `closureIds`, `resolutionOwner`, `canIdeHelp`, `recommendedTool`, `requiresConfirmation`, `rerunWillNotResolve`. This already supports **explain → identify specific missing evidence → propose IDE/local work**, not new AI detection.
- `haiec_get_consequence_delta` for two exact, comparable completed Evaluations; `haiec_get_agent_trace`, `haiec_get_governance`, `haiec_get_system_evidence` for related evidence and authority; `haiec_control_assurance`, `haiec_control_results`, `haiec_control_replay` for controls; `haiec_get_telemetry_status` and `haiec_list_evidence_binders` for runtime source readiness.

## 3. Gap between P05 and MCP

1. **P05 canonical DAI projection is not directly exposed as a scoped MCP DAI report read.** Actual P05 uses `assembleDaiEvaluations` + `projectDaiReport` in the session-only `/monitoring/dai/[surfaceId]` page. GitHub search/canonical registries did not expose a `haiec_get_dai_report` tool. Existing MCP Agent Audit and governance can narrate adjacent authority evidence but do **not** guarantee parity with P05's all-nine-dimension projection, `chainLanes`, `establishedWidening`, `unresolvedJunctions` or `asOf`. Don't tell connected assistants that a direct DAI tool is already live.
2. **No context-aware MCP investigation CTA on P05.** The global `UseWithAiAgent` helper exists on the System Workspace only, not on P05 / individual dimension/pivot. Users must manually transfer `aiSystemId`, DAI dimension and evidence references.
3. **HAIEC DAI evaluation ID and persisted U5 Evaluation ID are different ID domains.** `lib/assurance/dai-evaluation.ts` defines DAI `evaluationId` as a **deterministic digest over semantic inputs**. The P05 page labels it `eval <digest>`; do not pass this digest to `haiec_get_summary`/`haiec_get_master_report` or promise it opens a frozen U5 Assurance Evaluation. Copy contract must carry distinct `daiDigest` and **only when actually known** `assuranceEvaluationId`. P05 projection `asOf` derives from latest persisted facts, **not** necessarily a frozen evaluated snapshot date; say `current assembled evidence as-of` when no bound U5 evaluation was used.
4. **DAI assembler has a cross-basis input assumption:** when passed both a caller-chosen `surfaceId` and `evaluationId`, it checks evaluation organization but sets `scopedSurfaceId` from the eval **only if caller did not supply it**. Before adding a public MCP read with both inputs, enforce `evaluation.aiSystemId === surfaceId` or reject and ensure run-scoped attachment, envelope, declared fact and policy-as-of binding remain honest. **Not a confirmed tenant leak**; an implementation guard required to prevent compositional mixing. Existing no-`evaluationId` P05 read is a current assembled surface, not an immutable U5 report.
5. **MCP semantics are missing in context-specific UI.** Pending governance human approvals require explanation and dashboard-owned decisions, not `haiec_*approve*` spoofing. Agent-uploaded evidence requires explicit preview and qualified binder. No user-visible cross-client connection state is confirmed.

## 4. Customer UX contract: one shared contextual handoff, not a chatbot rewrite

**Flow:** From a fact/gap in HAIEC dashboard → **Investigate with AI agent** optional disclosure → user sees specific goal, exact system ID, exact Evaluation ID if available, relevant DAI dimension/closure/path IDs (sanitized identifiers only), required tool(s), unknowns/approvals and connection instructions → **Copy investigation prompt** → paste into configured Cursor / Claude Code / Devin / another MCP-capable agent → agent uses `haiec_capability_guide` & `haiec_preflight` for tenant/key/permissions, then read-only canonical tools → return explanation with **HAIEC-established facts / AI explanation or hypothesis / unknowns and evidence references / supported next permitted action** clearly separated. IDE can inspect local sources/logs with its native permitted tools; cloud clients may lack filesystem. Prompt copy is **not an automatically running agent, opened chat, or a session delegation**.

**Priority contextual surfaces (additive, capability conditional):**

| Page or state | Suggested visible affordance | Supported MCP workflow today |
|---|---|---|
| P05 DAI pivot / `#dim-SCOPE` or other dimension | `Investigate this delegation gap with an AI agent`; exact `aiSystemId`, DAI dimension, source refs, DAI assembled basis + as-of, explain qualification and suggested evidence | Current adjacent authority via `haiec_capability_guide(examine_action_authority)`, `haiec_get_governance`, `haiec_get_agent_audit` **when an exact U5 ID exists**. **Full P05 parity requires scoped read tool**. |
| P04 Assurance Case / Reports & Receipts / exact Evaluation | `Explain this evaluation / why this claim remains unresolved` with **exact U5 evaluationId** | `haiec_get_summary` → `haiec_get_agent_audit` → optional bounded `haiec_get_master_report`/`haiec_get_report` |
| Agent Audit `resolutionGroup`, frontier, NOT_ASSESSED, evidence gap | `Help investigate this missing evidence`; use canonical `verificationNeeded`, `closureIds` and `recommendedTool`, only after report read | `haiec_get_agent_audit.resolutionGroups`; agent can explain and prepare local evidence, but evidence never changes a frozen evaluation by itself |
| P06 Sources/Evidence onboarding | `Use AI/IDE to help connect this source or instrument telemetry` | `haiec_preflight` → `haiec_get_telemetry_status` / source read → optional explicit approved setup or intake |
| P07 Evaluate / Coverage | `Explain which analyzers actually ran and what's missing` | Exact completed Evaluation, Agent Audit/Report + source-specific analyzer execution owner; do not imply tool always returns all detection runs |
| P08 Controls & Operations | `Investigate why this control is NOT_ASSESSED` | `haiec_control_assurance` → results → replay; control catalog presence != native enforcement |
| P09 My Work / human decision pending | `Prepare decision briefing with AI` (READ-ONLY; reviewer still decides in dashboard) | Read facts via applicable scoped MCP tools only; never infer decision authority from MCP key or auto-sign a human approval |
| P10 Monitoring | `Investigate missing runtime witness / stale source` | `haiec_get_telemetry_status` → binder/source health; no monitoring alert/dispatch effectiveness overclaim |
| P11 Reports & Receipts / P12 provider usage | `Explain scoped report / evidence confidence`, or `Explain why provider attribution is unavailable` where a real read exists | Only promote when underlying canonical read is exposed; never fabricate cost, token attribution or receipt verification |

**Interaction rules:** Optional concise affordance near real decision/gap, not every row or a primary CTA that displaces deterministic next step. Reuse `UseWithAiAgent.tsx`/one shared builder; favor static, deterministic prompt templates parameterized by canonical IDs and enumerated goals. Context-specific only if source returns a scoped, valid identity. No raw evidence/text/name interpolation, prompt injection, PIIs, keys, customer secrets, untrusted URLs or unsanitized diagnostic logs in copied prompts. Prompt output format explicitly separates established HAIEC evidence, model interpretation, unestablished/UNKNOWN, citations, and proposed next step. Avoid user-visible raw MCP JSON and multiple competing assistant cards.

**Readiness states:** Connected MCP client is external and **cannot be inferred from dashboard session**. Show neutral `Works with an MCP-connected AI agent`, `Set up connection` link, and scope requirements; never `Connected` unless a real authenticated client connection is verified. When a target or permission is unavailable, suggest docs/manual read, not a dead button. Do not have dashboard ask user to paste or store API keys. No unauthorized direct-launch URL for external ChatGPT/Claude/Cursor without verified provider support.

**B. Read-only DAI parity decision:** Preferred if exact DAI data needs to be read by an IDE agent: add `haiec_get_dai_report` as a **read-only**, `report:read` scoped tool in `lib/mcp/ide-tools.ts` or canonical registry, returning `projectDaiReport` from **the same `assembleDaiEvaluations`** used by P05 with exact org/system membership check. Require explicit `aiSystemId`; optional *persisted U5* `assuranceEvaluationId` only when compatible and verified `aiSystemId`+org, and mark `basis: CURRENT_ASSEMBLED` vs `EVALUATION_BOUND`. Return DAI digest and U5 id **as distinct fields**; report read as-of, coverage, exact evidence refs and limitations; default bounded projection. Prevent incomplete/missing data from implying an empty clean result; verify DAI `evaluationId` is not accidentally presented as U5 report ID. Add to existing `examine_action_authority` goal + matching docs/manifest registry-derived tests, only after verifying on-main source+security contract. **Do not make a new DAI engine, scoring tool or generalized filesystem fetcher.** If existing canonical MCP read already exposes all fields by the time Devin checks, reuse it instead and don't duplicate.

**C. Pending action guidance (existing tools first):** derive assistant investigation suggestion from existing `resolutionGroups`, workflow next action/available status (no new inference). Keep actions explicitly typed: `READ_ONLY_ANALYSIS` vs `LOCAL_PREPARATION` vs `USER_APPROVAL_REQUIRED` vs `HAIEC_DASHBOARD_ONLY` vs `UNSUPPORTED`. AI agents can explain decisions, organize source-evidence requests, draft configs/remediation and help with authorized local proof gathering. They **cannot** authorize deployment, issue human approvals, waive UCP SoD/CAS, prove an installed PEP, claim a replay changed current state, or silently run scans.

**D. Later page sessions:** reuse shared handoff component only where applicable in P06 (source/evidence), P07 (evaluation/coverage), P08 (controls), P09 (human decision preparation), P10 (monitoring), P11 (reports), P12 (usage). No blanket navigation redesign or rewriting earlier screens. Identify actual report context owner before binding.

**Bottom line:** Make HAIEC's canonical MCP tools the *investigation companion* behind a context-aware dashboard invitation; AI helps understand/prepare, HAIEC qualifies/decides, and the human retains approval and operation authority.
