Permissions and trust boundaries

Repository access is deliberately scoped. Every permission has a purpose.

GitHub grants the App installation permissions. HAIEC resolves installation access server-side and binds the selected repository to a system in your HAIEC organization. This is not a request for your personal GitHub access token.

Repository contentsRead

Allows authorized source and configuration analysis. No repository file or branch content write permission is requested by this guide.

Pull requestsRead and write

Provides PR context and allows posting finding comments when the PR integration is enabled. This is a real write permission, distinct from source modification.

Repository metadataRead

Provides repository identity and selected governance configuration context.

GitHub install boundary

You choose the repositories

Keep installation permissions and selected repository access aligned to the minimum set needed.

HAIEC tenant boundary

Verified Source Asset

A source must match the authorized AI System, organization and active source status before an eligible remote run.

Credential boundary

Short-lived server-side credentials

HAIEC mints the scoped GitHub App installation credential server-side. The API caller uses its own HAIEC-scoped key.

What does not follow automatically: GitHub App authorization does not create delegated business decision authority. A source scan does not establish that a financial API call executed, a control actually blocked it or that compliance certification was achieved.

Setup, troubleshooting and developer questions

Get connected without granting more access than required.

Does installing the GitHub App automatically make the repository scannable?

No. GitHub installation authorizes selected repository access. The repository must also be connected to the appropriate HAIEC AI System as a verified, active Source Asset before a fresh full remote Assurance run can use it.

Where can I find the GitHub App installation link?

The current public guide links to the GitHub Marketplace search for HAIEC. Use the verified HAIEC App listing and its installation controls. The HAIEC /github/setup page is intended for the post-install continuation.

Why is my repository missing or not eligible?

Check which GitHub account or organization installed the App, which repositories were selected, whether access remains active, whether your HAIEC user is in the correct organization, and whether the Source Asset is connected and verified for the selected AI System.

Can HAIEC modify my repository source?

The documented installation permissions include repository contents read, repository metadata read and pull requests read/write. PR comments can be posted when enabled, but repository contents and branch modification are not authorized by those documented permissions.

What is the difference between a PR check and full remote Assurance?

PR checks inspect changed-file context and may post GitHub-native findings. Full remote Assurance must be explicitly initiated on a verified Source Asset and uses the canonical source/evaluation workflow. One is not proof of the other.

Do I need to give HAIEC a personal GitHub token?

No. The GitHub App installation is the source authorization path. HAIEC resolves short-lived installation credentials server-side. A separately scoped HAIEC API key is required for permitted API or MCP actions.

Can I run from Cursor or another MCP agent?

Yes, through a compatible client configured with the HAIEC Streamable HTTP MCP server and a scoped Bearer HAIEC API key. The agent can preflight the authorized system and eligible source, and invoke supported runs when requested.

Do missing policy and runtime sources prevent an initial code finding?

No. A supported code-reachability finding can reveal consequential capability within the scanned source. Additional policy, grants, DAI and actual target-side events answer more specific authority and execution questions.

What happens to my code in a remote scan?

The authorized repository is read by HAIEC remote scanner infrastructure via an installation-scoped credential minted server-side. For local/CI preview, available analysis runs on the customer machine or runner and submits supported qualified evidence instead.

Does HAIEC certify SOC 2 or issue compliance approval based on GitHub access?

No. Repository configuration and mapped findings may support a scoped assessment, but an installation, scan or example badge alone is not certification. Use the actual issued HAIEC evaluation and verification artifacts for precisely supported claims.

How do I check status or get help?

Use HAIEC's GitHub integration status page, review the post-install setup flow and contact the published support address if source verification or authorized scanning fails.
