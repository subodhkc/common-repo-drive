## 2. P12.1-G01 — CONFIRMED P1 project/workspace breakdown double attribution

**Current source:** `app/api/v1/inventory/costs/route.ts::loadAdminSnapshotCosts` independently groups **all** provider snapshots by `projectId` and by `workspaceId`. The final `projectMap` first includes every `byProject` group (including `projectId=null` in a `default` bucket) and then separately adds every **non-null workspaceId** group to the same map.

**Counterexample:** one provider row, `costUsd=$10`, `projectId=null`, `workspaceId="workspace-1"`. `byProject` puts $10 under `default`, `byWorkspace` puts **the same $10** under `workspace-1`. Therefore sum of displayed breakdown categories **$20**, while canonical `summary.totalCost` from aggregate is **$10**. This is confirmed by source control flow, not a demonstrated production dataset; data may or may not have actual workspace rows in the available test org. No tenant leak. It violates grouped financial consistency and should be addressed **before P13 polish**.

**Narrow fix (no new schema):** compute **ONE attribution key per snapshot**, derived from the complete source row: provider-qualified projectId when valid, else provider-qualified workspaceId, else `Unattributed`. Prefer `groupBy` on `['provider','projectId','workspaceId']` and accumulate each returned mutually exclusive tuple EXACTLY ONCE; avoid combining totals of two independent groupBy partitions. Preserve any canonical existing provider-specific attribution if schema declares another owner, but never count a row in two primary categories. If model returns both keys, choose a documented precedence and expose secondary field only as metadata, not a second additive bucket. Keep provider namespaces so identical project/workspace strings from different providers do not merge accidentally.

**Tests:** isolated Anthropic workspace-only row; OpenAI project-only row; one row with both; unattributed; two providers with same external ID; multiple rows mixed; group sum reconciliation within agreed rounding tolerance to `summary.totalCost`; browser project-card truth if displayed; source provider snapshot only, SDK `byProject` remains unknown. Actual `summary.totalCost` is separately aggregated and was not double-added by this specific bug.

**Scope:** only `loadAdminSnapshotCosts` grouping/response contract and its direct affected focused tests/UI labels. Do not reopen P12's complete aggregation, pricing, ingestion auth or usage/telemetry engines. One small P12.1 PR, required CI, merge Main and verify exact SHA Vercel READY; Common Repo update then advance.
