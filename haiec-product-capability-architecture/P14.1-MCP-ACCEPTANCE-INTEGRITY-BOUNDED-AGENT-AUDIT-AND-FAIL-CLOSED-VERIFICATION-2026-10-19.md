## 1. What the independent review confirmed — and what this PR fixes

The post-run review (`P14-G01`, `P14-G02`) confirmed two acceptance-integrity defects and one live crash:

1. **P14-G01 — false positive, `TEST_VERIFIED` as defect.** Committed `artifacts/_p14-evidence.json` showed `haiec_get_agent_audit` returned literal `RESULT_TOO_LARGE` — the MCP transport answered HTTP 200 with `result.isError: true`, and the old client passed any nonempty body (`status===200 && !!c.data`; strings have indexed keys, so `keys=0,1,…` looked like data). The original `17/17` was `SCRIPT_ASSERTIONS_PASS`, not 17 semantic tool successes. **Agent Audit had never been successfully delivered over MCP on a large report.**
2. **`RESULT_TOO_LARGE` guidance recommended the failing tool itself** (`Use … haiec_get_agent_audit …`).
3. **P1 crash found by the new strict client:** seeded malformed package rows (`reportJson` missing `profile`/`evidenceBundle`/`decisionReceipt`) made `verifyAssurancePackage` throw `TypeError` on unguarded nested access (`pkg.report.profile.profileId`, `bundle.members`) → `haiec_get_package` surfaced `INTERNAL_ERROR`, and the same crash path existed in the public verify route and publish flow.

Historical record preservation: the P14 record above is **not rewritten**. Its `17/17` remains visible and is hereby reclassified `SCRIPT_ASSERTIONS_PASS` per the independent review. This P14.1 record supersedes only the acceptance conclusion.

## 2. Shipped changes (one scoped PR, no engine work)

### `lib/mcp/server.ts` — bounded Agent Audit read (source-preserving)

`haiec_get_agent_audit` gains two selectors; `detail:"full"` remains the default and is byte-identical to before:

- **`detail:"bounded"`** — every scalar/top-level field verbatim (identity, basis, counts, `questionDisposition`, `authoritySummary`, full narrative text) plus `sectionIndex[]` (`sectionId`, `title`, `rowCount`) and `verificationItemIndex[]`, plus an `omitted` block with exact counts of what was elided. Nothing is fabricated or summarized; collections are replaced by indexes + disclosed counts.
- **`section:"<sectionId>"`** — returns exactly one section verbatim per call. Unknown id → `SECTION_NOT_FOUND` with a pointer to `sectionIndex` on the bounded read.
- Tool description updated to disclose that `full` can exceed the budget and to recommend `haiec_explain_evaluation` as the compact guided path.

### `lib/mcp/tool-context.ts` — honest oversize guidance

`RESULT_TOO_LARGE` now reads: use `haiec_explain_evaluation` (compact guided explanation), `haiec_get_summary` (disposition), `haiec_get_agent_audit` with `detail:"bounded"` / `section:"<id>"` (exact subsection), or `haiec_get_report` `profile:"summary"` — no longer points back at the call that just failed.

### `lib/assurance/u6-package.ts` — fail-closed verification

`verifyAssurancePackage` internals moved behind a guarded wrapper (`verifyAssurancePackageChecks`). Malformed persisted package JSON now returns `valid:false`, `integrityStatus:'INVALID_PACKAGE'`, all checks `false` — never throws. Downstream behavior stays fail-closed: publish → `CANNOT_PUBLISH_INVALID_PACKAGE`, public verify route → `INVALID_PACKAGE`, `haiec_get_package` → honest invalid-state instead of `INTERNAL_ERROR`. Valid packages verify exactly as before.

### `artifacts/_p14-mcp-client.js` — strict acceptance harness (rewritten)

- Positive cases require `result.isError !== true` **and** structured fields (exact `evaluationId`, verbatim disposition, `snapshotAt`, time basis, representative package selection).
- Negative cases assert `isError === true` **and** the exact expected code (`INSUFFICIENT_SCOPE`, `AI_SYSTEM_NOT_FOUND`, `RESOURCE_NOT_FOUND`, `SECTION_NOT_FOUND`), not "any non-200".
- `SKIPPED` is reported as SKIPPED — never counts as PASS.
- Targets are env-configurable (`P14_ORG_ID`, `P14_SYSTEM_ID`, `P14_EVAL_ID`, `P14_REVOKED_EVAL_ID`, `P14_NO_RECEIPT_EVAL_ID`) — no hard-coded tenant data; defaults point at the seeded `haiec_e2e` estate.
- Output is a ~3KB manifest: case ids, pass/fail/skip, actual status/error codes, payload digests — **no report bodies, no secrets**.

### `artifacts/_p14-mint-key.js` / `_p14-revoke.js` — parameterized for isolated E2E DB

Key provisioning now runs against `HAIEC_E2E_DATABASE_URL` (`haiec_e2e` — a dedicated seeded tenant dataset). The `PLAYWRIGHT_TEST=true` dev-auth mint no longer touches the shared customer Neon dataset. `P14.1` keys were minted and revoked **only** on the isolated DB.
