## 2. Source-observed residual notes (P2 backlog, not blockers)

- **P12.1-R01 optional secondary-workspace label lossy:** the bucket key `provider|project|projectId` intentionally merges multiple `groupBy` tuples that have the same project with DIFFERENT nonnull `workspaceId`; on each merge the mutable `existing.secondaryWorkspaceId = g.workspaceId` retains only one workspace, whichever row is processed last. Exact project COST/COUNT is conserved, but the single metadata value can misrepresent the plurality. Source-observed, not reproduced with a real provider dataset. If later exposed to customers with multi-workspace per project, use a bounded/sorted list of observed secondary IDs or `multiple workspaces`; do not display one arbitrary ID as exhaustive. Test two workspaces sharing a project. No production claim of accurate one-to-one secondary mapping.
- **P12.1-R02 delimiter-key ambiguity:** `provider|kind|id` is a display/API key; should not be parsed as security identity or assumed collision-proof if external IDs could include delimiters. Prefer tuple-key escaping or a stable compound serialization only if consumers require decoding; current backend remains org-scoped. No confirmed exploit or actual ID collision.
- **P12-R03 whole-provider financial truth:** full `aggregate` proves completeness over stored matching rows, **not** provider invoice coverage, dedup across different admin keys, accurate price list, or effect attribution. SDK rate estimate is January 2026 static table. Preserve labels and source limitation.
- **P12-R04 standard selected-org path:** `OrganizationSwitcher` updates Zustand state then full-page reload, while P12 page request-sequence guards change only when fetching and page effects are keyed to range/source, not org. Standard user switch reloads; alternate programmatic store-only switch not independently tested. Do not call this a proven tenant ACL bug. Include one org-switch and mid-flight response regression in shell acceptance.
