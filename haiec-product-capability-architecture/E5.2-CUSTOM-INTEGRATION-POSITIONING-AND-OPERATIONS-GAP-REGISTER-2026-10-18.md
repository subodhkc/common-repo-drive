## 1. What is demonstrably available and marketable today

A reusable **integration template** plus an engineering **design / feasibility review / scoped customization pilot** can be offered, using the customers' owned gateway, tool host, SDK middleware or IAM/PEP. Technical scaffold (in Common Repo) is TypeScript injected-interface mediation; tests establish that a *supplied* bound ALLOW calls a test adapter, DENY/HOLD/INDETERMINATE do not, wrong identity/digest/expiry do not, missing atomic-claim adapter blocks execution, and target exception is reported as unknown rather than safely retryable. It is **not an integrated customer-deployed guard** and does not implement real decision computation, durable claim or real target. A claimed successful dispatch is deliberately NOT_VERIFIED as a business effect.

**Existing app foundation:** E5.1 read projection, native adapter interface, local Kill Switch guard, specialized C16 in-path control decision, approved envelope, scoped human decisions and P09 repaired packet read entitlement, UCP Control Proof, E4 source evidence. In app current source, production native enforcement registry remains **empty**, fixture only in development. **P09 PR #2257 merged to Main \`47af59ef8a614b67e9300a7c2453d3f2cb72da0a\`**, hence older guidance saying P09 still in progress is historical. P10 Monitoring remains the next page workflow; reference code in Common Repo was created independently of the app and does not count as a product deployment.

## 2. Generic operational transaction (illustrative only; not six mandatory jobs)

```text
Discover exact tool + boundary + acting principal
    ↓
Locate actual intercept point and authorized target connector
    ↓
Freeze/resolve active policy + permitted operation/resource
    ↓
Agent attempts exact action: actor, target, action digest, attempt ID
    ↓
Trusted authorization result ──────┬─ DENY / unknown → no target call
                                   ├─ HOLD → My Work human packet;
                                   │         pending cannot execute
                                   └─ bounded ALLOW → durable claim
                                                         ↓
                            customer PEP dispatch (no alternate bypass)
                                                         ↓
                      guard disposition / provider acknowledgment / readback
                                                         ↓
                  qualified evidence → Monitoring / response → Verify & report
                                                         ↓
                      policy change / revoke / recover → fresh evaluation
```

**Critical:** The test skeleton *does not* implement the top-level discovery, policy resolver, My Work request adapter, production claim store, target PEP, readback or automatic resume. HOLD returns a non-executable packet identity only; an approved caller must resubmit and obtain a fresh independently bound ALLOW. One-time claim is a REQUIRED injected port, not a shipped durable implementation; don't promote mock tests to exactly-once guarantees.

### Recommended order without sprawl

**Now (already completed at source/reference level):** Minimal provider-neutral reference scaffold, test contract, marketing option + honest availability. Preserve UX-P09 completed release and next P10 Monitor project.

**After gateway/customer consent:** select one target native PEP; show real installed policy fingerprint, action attempt, guard refusal, scoped human approval, actual effect and independent readback. Test bypass, cross-system, race and revocation. Only then promote from "Custom integration offering" to "Customer pilot verified" for that **specific target**.

**Later (P11–P13):** Connect exact receipts, usage and cost truth, topology edge inspector, operational polish and customer integration proof to existing owners, subject to authentic evidence.
