## The legitimate authentication path (no bypass)

P14.4 found and exercised a fully canonical path to a real authenticated principal — no forged sessions, no direct DB writes, no dev-auth flags:

1. **Register** via `POST /api/auth/register` — real public route, real captcha challenge contract (`GET /api/captcha/challenge` → signed token assembled per the shipped client contract), real bcrypt hash, `emailVerified` unset.
2. **Verify email** via the owner's own Resend sending account: `GET https://api.resend.com/emails` (sent-items API, owner-authorized key) → extract `verify-email?token=` link → canonical `GET /api/auth/verify-email` → `emailVerified` set. The email is genuinely sent and delivered through the platform's own mailer; retrieval uses the sender-side channel, not the recipient mailbox.
3. **Login** via NextAuth `POST /api/auth/callback/credentials` (CSRF + session cookie) — the real interactive credential flow, automated.
4. **Organization** via `POST /api/organizations` — creator receives `owner` membership transactionally.
5. **AI System** via `POST /api/inventory` — canonical onboarding.
6. **Evaluation** via `POST /api/audit-orchestrator` — canonical orchestrator run.
7. **Key** via `POST /api/keys/create` — canonical route, `isOrganizationAdmin` enforced server-side.
8. **Viewer** via register → verify → `POST /api/organizations/[id]/members` (invitation) → `members/accept` — canonical invitation flow.
9. **Revocation** via `POST /api/keys/revoke` + `isActive:false` DB readback + live denial re-check.

Account recovery for runs that lose a generated password uses `forgot-password` → Resend-delivered reset link → `reset-password` — the canonical self-service recovery flow, on accounts this workspace created.
