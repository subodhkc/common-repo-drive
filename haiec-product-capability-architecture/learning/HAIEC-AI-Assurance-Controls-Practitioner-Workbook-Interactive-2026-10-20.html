02 / The assurance distinction

Which layer supports this claim?

A control review is strongest when it names the question, source, test scope, decision and possible consequence. Click any facet to learn what it establishes and what it does not.

What can start immediately?

A source-backed code-capable tool path can be actionable even before an IAM provider, policy package or runtime source is connected. Missing sources sharpen the follow-up, not erase an established source finding.

Source-first, evidence-bound

What is not one green score?

A control may be applicable but unevaluated, present but ineffective, or tested for one version while production has changed. Record each fact against its own identity, source and time.

No universal PASS state

Practice this explanation

"A02 is in the catalog. A code-source candidate appeared. No eligible native control test has run for this system. We can investigate the capability, but cannot yet claim a tested pass or an applied runtime block."

Truth and scope notes

Catalog count and flag definition
Exactly 45 entries, including three specialized control tests. 15 launch-priority metadata flags and 11 visibility-supported IDs are not counts of verified or satisfied controls.
DAI and evidence
Use the five independent evidence planes. Ordinary policy constraints do not automatically establish delegated discretionary choice. ISAF v2 is a separately described research method, not a claim all its semantics are deployed.
Operational and client context
Native runtime protection and target-effect confirmation require real customer-specific integration, permitted test scope and independently sourced witnesses. The educational workbook never runs a tenant action.
Control result identity
Catalog, visibility, native test, U5 assurance, human decision, monitoring and target proof each retain their own scope and source, and cannot be merged into a universal safety indicator.
