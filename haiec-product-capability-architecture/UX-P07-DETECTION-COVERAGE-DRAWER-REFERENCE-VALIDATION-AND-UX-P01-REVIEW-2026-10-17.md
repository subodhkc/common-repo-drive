## Executive decision — coverage is a missing customer explanation layer, not a new detector engine

**Adopt:** compact eight-family participation matrix, source-mode-specific evidence, analyzer-level expanders, "What this exact run established / did not establish", and a real qualified "what evidence could help next" link. This makes HAIEC's static breadth (AppSec, prompt/RAG, tool/MCP, supply chain), runtime testing, telemetry, IAM and controls visible **without pretending all run on all sources**. Preserve E6.2 **five evidence-plane availability**, current Assurance Case and technical scans; place this in the selected exact-run **HAIEC Assurance Engine results** (UX-P07) with an optional contextual inspector from UX-P04 Assurance Case. Never substitute it for authority-plane coverage or current operational control readiness.

**One design grammar:** Why this selected facet → analyzer/producer that actually ran (or not) → what evidence/finding was established, with scope → unknowns/limitations → eligible next source or detailed result. Reuse one contextual inspector convention; do not build an unrelated nested overlay or a second proof store.

| **Matrix "Full" badge / source-mode green icon** | **Reject unqualified semantics** | Prefer participation **EXECUTED / PARTIAL/UNKNOWN / NOT_EXECUTED / NOT_SELECTED / UNSUPPORTED / FAILED / HELD** backed by available owners. **Most serious false claim:** Mock local bundle scenario says it supports static reachability / a fixed subset of “15 remote-only rules,” yet the app's S13-C source-mode contract explicitly distinguishes local evidence-only scans with unavailable operation coverage. Fix by reading exact accepted scan type and operationCoverageIntelligence; if missing, display producer gap and scoped supported evidence, never static repo analysis.

**Second critical separation:** Exact-run analyzer *execution provenance* differs from **AI Assurance Engine claim sufficiency**, and both differ from **control installed/monitored/enforced** and **target effect**. The UI must preserve all four meanings; no one green “full.”

## E6.2 + UX-P01 implementation review

**Confirmed through [PR #2231](https://github.com/subodhkc/haiec-website/pull/2231):** \`Main\` \`75ea4ef11\`; current [QuickStartWizard](https://github.com/subodhkc/haiec-website/blob/Main/components/dashboard/QuickStartWizard.tsx) provides the three peers **Explore System / Choose Goal / Connect or provide evidence**, reuses \`SystemFirstOnboarding\`, maps E1 jobs and source contract, and fetches exact per-system \`/api/inventory/systems/[id]/capabilities\`; registry and source states are qualified. User-supplied release record reports 111/111 focused tests, scripted 1440px/390px screen review and prod deployment success. **Authenticated organization browser flow remains \`NOT_RUN\`.** Do not treat screenshots from demo/no-org as full customer acceptance.

**Follow-up attention from source inspection:**
1. **Stale in-flight capability read when switching systems rapidly:** \`QuickStartWizard.loadCapabilities(systemId)\` sets shared \`caps\` from any response without verifying that its system is still selected. If A→B responses arrive B→A, an A payload could appear under B's picker. This is a **potential source-context leakage within current org's selected systems**, not a verified cross-tenant breach; server tenant scope still matters. Address in a *narrow* UX-P01 correctness follow-up or next authorized shared-component pass; use request ID/cancellation/current-selected-ID guard, clear context on switch, focused out-of-order-responses test. Do not broaden UX-P02 page work unless quick fix is separately included with nonregression tests.
2. **Null/demo membership fallback:** project reports registration restored when no org membership; read-only viewer is explicitly blocked in UI, but no-org/demo mode should remain clearly preview-only and server write permissions authoritative. Recheck with actual authenticated org roles before enabling customer-visible submission. Do not treat null membership as an affirmative production authorization grant.
3. **Visual signoff remains incomplete:** 1440/390 synthetic captures ≠ real org viewer/approver/source-ready click-through. Capture planned QA and don't claim an authenticated complete journey.

These are bounded leftovers, not a reason to undo the successful three-entry design.
