## Content and credibility

- **Executive value:** clear questions for CEO/CTO/CISO; value phrased as a decision HAIEC can support, not measured financial ROI.
- **Technical separation:** connection/receipt ≠ qualified evidence; declared permission ≠ effective grant; a DAI comparison needs appropriate delegation source; source reachability ≠ exercised tool; approval ≠ dispatch; a configured kill switch ≠ target effect.
- **C1 manufacturing:** persisted canonical HAIEC evaluations of **synthetic** records show wrong-target divergence and REVIEW; subsequent factory hold and human review are simulated. Source [judge guide](https://github.com/subodhkc/manufacturing-ai-assurance-haiec/blob/main/docs/hackfw/JUDGE-GUIDE.md).
- **C2 TM Forum:** archived C7/C9/C16 scoped test results. Token cap result does not show target denial. Participant-published evidence is not organizer-certified. Sources [register](https://github.com/subodhkc/tmf-2026-evidence/blob/main/register.yaml) and [verification limits](https://github.com/subodhkc/tmf-2026-evidence/blob/main/SUBMISSION_PROVENANCE_AND_VERIFICATION.md).
- **POC:** Current [HAIEC Enterprise](https://www.haiec.com/enterprise) describes a $25K–$75K scoped evaluation typically 4–8 weeks **after readiness**; final terms in the SOW. Explorer keeps the contract scoped.

## Remaining release gates

1. **P0: Live URL verification / publication rights.** HAIEC Enterprise page was publicly readable; manufacturing and GitHub code-render web views were not independently fetched by that web reader in this turn. The TM Forum register and manufacturing judge guide **were** read through the connected GitHub app. Verify target-site redirects and media rights before embedding assets; prefer linking public archives to redistributing organizer materials.
2. **P0: Latest HAIEC Main release truth.** Confirm source/tenant readiness for registered detectors, the catalog, AppSec/LLMVerify packages, GitHub App, local CI preview, monitoring, runtime testing and native target adapter. Do not promote registry counts to executed customer coverage.
3. **P0: CSP/hosting.** Integrate split HTML/CSS/JS into existing website approved origin (not the inline standalone bundle) and do not weaken the live CSP.
4. **P1: Actual assistive technology.** NVDA/VoiceOver, keyboard focus flow, 200% zoom and manual contrast, including full names/labels. A browser DOM smoke is not WCAG certification.
5. **P1: PDF user experience.** The full PDF is an appendix of 26 pages rather than 12 slides. If needed, separately curate a 3–5-page executive extract; do not shrink technical diagrams until illegible.
6. **P1: Cross-browser / production verification.** Safari/Firefox and real deployment/mobile checks after review. No automated claim that native blocking is active.

## V4.1-only changes

Print styles only: A4/page numbering; cleaner selected-view print; no hard page break for closing summary; hide editor-only 'Back' button in PDF; preserve selectable view content and readable scale. Revision labeling updated. **No new tabs, data, agent graph, detectors, evidence evaluation, approvals, MCP services, runtime controls, or website deployment.**

**Disposition:** Controlled buyer/stakeholder HTML share: **GO (with qualifiers)**. Website publication: **HOLD for P0 release gates**. Original V4 remains archived for comparison.
