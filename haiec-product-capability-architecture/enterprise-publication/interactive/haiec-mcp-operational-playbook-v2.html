CLI & REST alternatives

HAIEC's supported complete remote source-assurance workflow is via MCP or REST API v1. A universal fully released HAIEC local CLI is not available: local/CI analysis remains preview/enterprise POC, and GitHub Action v2 is not released.

Authenticate and inspect verified source

export HAIEC_BASE_URL="https://www.haiec.com" export HAIEC_API_KEY="$(your-secret-manager-read-command)" export HAIEC_AI_SYSTEM_ID="<actual-system-id>" export HAIEC_SOURCE_ASSET_ID="<verified-source-asset-id>" curl -fsS -H "Authorization: Bearer $HAIEC_API_KEY" "$HAIEC_BASE_URL/api/v1/systems" curl -fsS -H "Authorization: Bearer $HAIEC_API_KEY" "$HAIEC_BASE_URL/api/v1/systems/$HAIEC_AI_SYSTEM_ID/evaluation-sources"

Run actual static source assurance (orchestrated)

RUN_KEY="$(uuidgen)" curl -fsS -X POST "$HAIEC_BASE_URL/api/v1/assurance/runs" \ -H "Authorization: Bearer $HAIEC_API_KEY" \ -H "Content-Type: application/json" \ -H "Idempotency-Key: $RUN_KEY" \ -d '{"aiSystemId":"'"$HAIEC_AI_SYSTEM_ID"'","engines":{"static":{"enabled":true,"executionMode":"api","sourceAssetId":"'"$HAIEC_SOURCE_ASSET_ID"'"}}}'

Poll and read exact evaluation

# Use runId/evaluationId from the API responses curl -fsS -H "Authorization: Bearer $HAIEC_API_KEY" "$HAIEC_BASE_URL/api/v1/assurance/runs/<runId>" curl -fsS -H "Authorization: Bearer $HAIEC_API_KEY" "$HAIEC_BASE_URL/api/v1/assurance/evaluations/<evaluationId>/summary" curl -fsS -H "Authorization: Bearer $HAIEC_API_KEY" "$HAIEC_BASE_URL/api/v1/assurance/evaluations/<evaluationId>/agent-audit" curl -fsS -H "Authorization: Bearer $HAIEC_API_KEY" "$HAIEC_BASE_URL/api/v1/assurance/evaluations/<evaluationId>/master-report"

Action & authority assurance

Inventory broadly. Investigate consequentially.

Do not create one giant report for every greeting, menu, FAQ or configuration field. Show the full discovered action inventory, group related actions by consequence family, and produce detailed evidence cases for consequential actions, unexpected changes, and material exceptions.

Completeness rule: exposed MCP tools are not necessarily every internal capability; recognized source operations are not necessarily reachable; observed traces are not necessarily complete. Every percentage needs a source-bounded denominator.

Who decides what is consequential?

HAIEC proposes a risk-sensitive classification from qualified action semantics, effects and evidence. The accountable customer approves the operating boundary, data classes, thresholds and exceptional actions. Unknown or generic tool mappings require review, never silent approval.

What to show in the report

Executive: system/family coverage and high-risk cases. Action detail: requested, authorized, effectively granted, code-capable, observed, source/evaluation basis and proof gaps. Appendix: all recognized actions and unknown coverage.

The client invites you to the authorized HAIEC organization and separately authorizes protected source access and endpoint tests. Your own consultant account cannot simply assert customer ownership.

What actually orchestrates

Static source assurance

Verified repo+branch+consent → source analyzer → qualified source/capability evidence → deterministic Assurance → frozen evaluation.

Active runtime test

Runtime preflight → explicit authorization → separate test executor → completed result → attach to a new evaluation.

Passive telemetry

Approved binder config → customer instruments emitter → accepted, qualified events → new evaluation if needed. Configuration alone is not monitoring proof.

Human approvals only where they matter

Access to a private source, source binding, evidence upload, active runtime tests, consequential configuration writes, approval of operating policy, deployment decisions, target-side control enforcement, package publication. Read-only inventory/preflight should not require unnecessary repeated approvals.

Truth boundaries: DRAFT ≠ APPROVED · CODE_CAPABLE ≠ OBSERVED · IAM simulation ≠ effective grant · TRACE ≠ target effect · CONNECTED ≠ EVALUATED · CONFIGURED ≠ ENFORCED · REPORT ≠ CERTIFICATION.
