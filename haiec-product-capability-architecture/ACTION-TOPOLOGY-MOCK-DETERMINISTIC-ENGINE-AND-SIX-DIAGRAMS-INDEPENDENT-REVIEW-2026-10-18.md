## 1. Uploaded HTML mock: what actually works

The file defines **15 node objects**, **15 edge records** (**11** visually 'qualified', **2** candidate, **2** 'missing') and hard-coded per-node/edge evidence prose. It is a static demonstration: **no live HAIEC API, MCP call, source scanner, DAI comparison, target readback or approval request** runs from the HTML. Visual scheme: Agent → Capability → Tool → Target → Consequence, with root/child agent, alternative data-read branch and an unregistered unknown branch.

Headless Chromium `set_content` smoke at **1440, 768, 390 px** verified graph/table switch, a runtime lens, selecting a table edge, opening inspector, Escape close and no page-level JS exceptions. At 390px the canvas is CSS-transformed to 0.65 on a fixed 1,180px internal width, so users must horizontally scroll to inspect right-hand target/effect columns; the table's first container had **356px client width but 496px scroll width**, rows use only `<tr onclick>` without keyboard focus. Inspector `role=dialog aria-modal=true` opens **without focus moving into it**, no confirmed focus trap/restore. Diagram may be navigable by mouse but **not a production accessibility reference**.

**Confirmed interactive bug:** 'Coverage gaps' lens counts 4 nonqualified edges but `edgeMatchesLens('coverage')` returns `true` for *every* edge; clicking it left **15/15 edges and 15/15 visible nodes** unchanged at 1440 and 390px. It did not isolate gaps. This and mobile scrollbar state are non-authoritative mock defects, not bugs in HAIEC's existing map.

Mock 'Open full evidence packet' and 'Focus on connections' use toast-only previews; there is **no canonical evidence drill-through**. Selected node inspector/edge inspector ideas are good; their preview actions are not working HAIEC navigation.

## 2. Mock evidence-truth faults — never transplant

|---|---|---|

| Signed root grant → child delegation → capability → MCP tool → provider target → independently verified refund as one proven runtime chain | Static labels/dummy refs lack exact issuer/principal, approved root scope, child narrowing, tenant-bound handoff/trace join, matching dispatch to target ack, and independent readback. | Per-system graph can be factual where canonical IDs exist; **cross-system delegated effects remain E62 PROPOSED/UNVERIFIED** until deterministic joins prove each hop. |
| Stripe target 'PEP v2.1 enforcement active' / ACK / refund readback | Synthetic assertions; no real provider adapter, actual target mediation, independent balance delta or current customer protection proven here. | `CONFIGURED != DISPATCH_ELIGIBLE != APPLIED_AT_TARGET != EFFECT_VERIFIED`; never fabricate PEP/readback. |
| Customer DB: independent readback 'no data left tenant boundary' | A bounded query/observation does not establish global absence of cross-tenant egress or future correctness. | Source-specific authenticated observations only; not a universal non-exfiltration guarantee. |

**Sanitation:** Example identities (`alice.chen@example.com`, hardcoded KMS and Stripe references, transaction IDs), alleged signed grant and mock policy versions are **fixtures**; they must never become canonical HAIEC tenant facts or operational evidence.

## 3. What to learn and adopt selectively

**Worth adopting as presentation improvements, without a second engine:**

1. **Explicit relationship inspector.** Add/reuse a selected edge's *why this edge exists* with exact `canonicalRelationId` or known `TopologyEdge.id`, `kind`, `joinBasis`, source/scan/evaluation/time, source evidence and first unestablished continuation. If relation-level provenance isn't available, mark **not established**, no guessed evidence join.
2. **Lens-aware relation table** alternative to canvas at all sizes, keyboard-focusable, column labels preserved on 390px. Table should reflect same selected canonical projection and lens; no new graph data.
3. **Show first proof break / path frontier** and one real eligible next action. Reuse ActionProofTrace `continuityFromPrevious`, `proofFrontier`, source gap and Agent Audit `resolutionGroups`, not a new generic anomaly model.
4. **Fact type and degree of evidence**: classify *source-established relation*, *candidate*, *unknown/declared*; independently show five-plane status, DAI comparison and effect-proof state where those exact owners have a matching identity. Red only for an actual scoped finding, not missing evidence.
5. **Per-path graph focus** and structured inspector with `what established`, `what cannot establish`, `evidence pointers`, `next permitted action`. Avoid overview graph exploding in dense customer estates; use existing semantic zoom/layout and stable IDs.
6. **MCP/IDE handoff**: `haiec_get_agent_trace` read-only, `system:read`, supports `basis=current|evaluation`, exact `evaluationId` when historical, and `format=json|mermaid`. Copy a bounded prompt to inspect exact agent trace, DAI and Agent Audit, compare evidence frontiers, and link exact reports; agent interpretations are hypotheses, **not new evidence**. Never infer dashboard login authenticates external MCP. `haiec_submit_trace_facts` requires `system:create` + `userConfirmed:true`, explicitly **DECLARED only**, not proof: do not auto-call through investigation UX.

**Not worth adopting:** a new topology engine, per-customer fictional Stripe/PEP target, universal green/red edge scoring, static 1,180px canvas, fabricated node UUIDs, a mandatory five-node pipeline, unbound graph-to-effect relation inference or a new cross-system proof verdict.

**Recommended ownership/timing:** keep current **UX-P08 Controls & Operations** and later **UX-P09 My Work** uninterrupted. File *Action Topology Evidence Inspector / Graph-Table semantic parity* as a narrowly scoped **future Action Map/UX-P05 extension or P13 polish**, only when source-bound. Cross-system issuer/handoff/ack/readback engine is **E62 gated** separate backend work, not presentation backlog disguised as done. Direct P08/P09 links may reference an existing system Action Map but must not claim a per-control graph edge without bound evidence.

**Exporter hardening candidate (P2, not another immediate sprint):** `lib/topology/agent-trace-mermaid.ts::safeId` maps *every* non `[A-Za-z0-9_]` character to `_` without a collision check. Distinct node IDs like `a-b` and `a_b` can therefore collapse into one Mermaid identifier if such canonical/declared node identities occur. Stable base graph IDs hash canonical tuples, but the export helper itself is **not an injective mapping**. Before exposing Mermaid as independently verifiable graph identity, add a stable hash suffix or collision-safe ID allocator and a fixture for punctuation variants. This is a **code-level collision possibility**, not a reproduced production collision.

The existing source-owner separation is strong. UI can attach *source facts and proof gaps* to a graph; it must not **derive execution or authorization from visual adjacency**. For a new native target effect, require exact separately qualified target-owner record, not an imported screenshot or an LLM explanation.

## 6. Backlog disposition / acceptance boundary

- **NOW / documentation:** Record this distinction, the actual Mermaid MCP capability and six-diagram semantic validation in Common Repo and cite here from latest handoff/matrix/spec; do not edit P08 files/PR.
- **P13 / future topology UX owner (P2):** on existing Action Map/Constellation/Agent Trace, study graph/table parity, focus on first proof frontier, exact edge inspector with provenance and independent evidence planes, mobile accessibility; only additive if not already present. Keep source/scan/eval/basis identity and role.
- **P2 exporter hardening:** add deterministic collision-free Mermaid node identities and narrow export tests if user-visible export identity needs assurance. Do not call a graph proof receipt just because source text is stable.
- **E62 backend gating (P1 before *claim*, not P1 current defect):** no green multi-system delegated effect without issuer/principal/digest/handoff/trace/revocation/target ACK/independent readback joins. Do not make it an automatic UX prerequisite.
- **MCP parity:** reuse **`haiec_get_agent_trace(format:'json'|'mermaid')`**, optional `haiec_get_dai_report`, `haiec_get_agent_audit`, `haiec_get_master_report` and `haiec_capability_guide`. Existing `haiec_submit_trace_facts` is **an explicit authorization-gated DECLARED write**, never silently inferred graph input.
- **Do not invent:** second diagram engine, graph-based risk score, implicit human approvals, per-edge 'all planes verified' badge, actual native enforcement, event-level effect proof, organization-wide chain, or an automatic LLM-generated canonical topology.
- **Tests for eventual owner:** exact per-scan identity; current/evaluation non-mixing; code-only edge never 'authority fully qualified'; missing joins remain visibly broken; source-only vs observed vs authenticated target outcome; same-name cross-system negative; multi-tenant failures; mobile 390px/table keyboard and labels; Mermaid punctuation collision; no secret URLs/credentials. Full external KestrelVoice-via-HAIEC-MCP operational capture remains separately deferred and must be narrated/edited/captioned layer by layer using authorized real test state.

## Final product decision

**Learn from the mock's graph-inspector user journey, NOT its asserted consequences. HAIEC can already produce source-qualified topology and portable Mermaid from deterministic owners today.** The moat is exact relation identity + explicit incomplete proof across source, delegated policy, code, runtime, governance and independent effect, not visually drawing a convincing five-column graph. Keep the three-pillar/six-job story and current P08/P09 release cadence intact.
