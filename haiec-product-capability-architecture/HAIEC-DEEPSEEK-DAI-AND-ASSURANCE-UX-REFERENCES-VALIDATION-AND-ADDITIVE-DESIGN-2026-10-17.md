## Permanent product decision: enhancement-on-top, not replacement

**These mocks supply visual grammar, storytelling and affordances; HAIEC supplies the authoritative data, actions, evidence qualifiers, permissions, reports and technical depth.** Every adoption must pass a **preservation inventory** of the current page's existing tabs, links, role actions, diagnostics, advanced detail, immutable report identifiers, evaluated-snapshot scope and current-source views. Do not “simplify” away advanced capabilities, existing Control Proof, 45-control catalog, monitoring, static rule families, prompt/RAG, CI/GitHub App, API/MCP, human evidence uploads, assurance profiles, delegated-action details, per-operator approval flows or receipt verification.

Design separately in the existing [13-session UX program](HAIEC-PAGE-BY-PAGE-UX-DESIGN-AND-VALIDATION-PROGRAM-2026-10-17.md). **UX-P01 Start Here remains the current next bounded page.** Incorporate the new mocks in **future UX-P04 System Assurance Case, UX-P05 Agent Action/DAI, UX-P07 Evaluation coverage, UX-P08 Controls, UX-P12 Provider Usage** *when those sessions are individually active*. Do not interrupt or co-edit UX-P01 to transplant a different page.

## 1. DAI SAMPLE — what to adopt

### High-value design patterns (selective reuse)

| DeepSeek element | Validation / why valuable | Reuse in current HAIEC |
|---|---|---|
| **Per-hop delegated chain:** root agent → handoff → child agent → tool → provider acknowledgment → effect readback | Strong narrative for a consequential multi-agent action, preserving causal/evidence boundaries instead of treating one log line as the entire chain | Add a **Delegated Action Chain detail view** within the current Agent/Action/Constellation experience. Preserve existing Action Map lenses and canonical `consequenceRelationId`, path IDs and selected evaluation. |
| **“Jump to pivot”** link, visually distinct candidate/pending/qualified connectors | Efficiently moves reviewer to the first material deviation or missing join | Introduce “First mismatch / First unknown” *only from deterministic qualification states*, with stable deep link and evidence refs. Nonlinear/multi-branch workflow must show multiple pivots rather than falsely identify one first pivot. |
| **Visible “What this means,” exact fields and expandable evidence per hop** | Makes the source/effect story explainable at both executive and SME levels | Use common inspector contract **Why → Established → Unknown → Evidence/provenance → Next permitted action**; keep source signature, issuer, subject, operation, policy digest, observed time and limitations. |
| **DAI nine-dimension parent/child comparison table** | Makes scope widening comprehensible (OPERATION/TARGET/SCOPE/MAGNITUDE/DURATION/APPROVAL/DATA_CLASS/ENVIRONMENT/GEOGRAPHY) | Reuse canonical `dai-evaluation.ts` outputs with `MATCHES / BROADER / NARROWER / MISSING / UNKNOWN`, evidence refs and plane basis. Clicking a truly widened dimension navigates to qualifying observation, not mock data. |
| **Chain and accessible table alternatives** | Graph alone is difficult to audit with keyboard/assistive technology | Provide two synchronized views of **same canonical read model**, preserving each source and limitation; keyboard/focus/scroll restoration and real table headings. |
| **Good/bad/partial scenario storytelling** | Excellent educational/demo resource | Keep as **clearly synthetic training fixtures** on demo pages; do not make scenario tabs appear to swap actual customer findings. |
| **Export receipt / Open Assurance Case affordances** | Appropriate links *if exact underlying record exists* | Enable only with an eligible frozen evaluation/receipt and authorized route; otherwise show why unavailable. Do not claim exported from a toast. |

### Required semantic fixes — do not copy verbatim

1. **Cross-AI-System fully verified chain is NOT an implemented universal capability.** The existing same-system UCP witness intentionally requires equal `organizationId`, `aiSystemId`, and `runId` and is declaration-bounded. Cross-system issuer-authenticated grant, parent/child principal identity, root scope, trace and independent target readback remain the five gated dependencies in the cross-system engineering contract. Show **candidate/unqualified** join until completed and source-qualified.
2. **Missing root grant ≠ 9/9 violated.** The mock's no-grant scenario sets every dimension to false and renders “9 flagged”; current DAI explicitly locks `MISSING_DELEGATION_EVIDENCE != DELEGATION_VIOLATION`. Mark each missing dimension `MISSING/UNKNOWN/NOT_ASSESSED`, not a confidently broader child. A proven scope widening is separate from missing authority.
3. **DAI's real disposition vocabulary is not the sample's invented chain-status enum.** The engine defines `INSIDE_ESTABLISHED_DELEGATION`, `CAPABILITY_OUTSIDE_DELEGATION_MEDIATED/UNMEDIATED`, `GRANT_BROADER_THAN_DELEGATION`, `OBSERVED_OUTSIDE_DELEGATION`, `UNRESOLVED_DELEGATION_EXPOSURE`, `NOT_ASSESSED`; the sample's `AUTHORIZED_DELEGATION_ESTABLISHED`, `TARGET_EFFECT_VERIFIED`, `HANDOFF_OBSERVED` are distinct proposed **edge/proof** labels, *not* replacement overall engine dispositions. Never reduce nine dimensions to boolean match/no-match.
4. **“Every step qualified” is scope-specific only.** Validate issuer-to-principal link, cryptographic producer authenticity, policy scope/version, revocation-as-of, delegated depth, target acknowledgment and independent effect identity. A signed collector trace does not itself prove authority or cause. A provider acknowledgment proves only that qualified provider statement; it is not target execution/committed refund.
5. **Independent readback needs causal target identity, not only a balance amount.** The sample's Stripe balance delta is suggestive, not sufficient without exact refund/transaction/resource reference, baseline/read time and independent source/lineage. Different-source credentials do not automatically mean independent evidence lineage.
6. **Valid effect and invalid authority can coexist** (revoked mid-chain example is useful). Show these as distinct statuses, never one success pill. Revocation needs issuer-authenticated event and exact effective time; lack of grant record alone cannot prove no grant existed elsewhere unless source completeness is established.
7. **Evidence refs in sample are hardcoded illustrative strings, not clickable citations.** A production row needs exact org-scoped source IDs, digests, source authority, time/provenance, and opening actions. No emails, KMS identifiers, external account details or credentials exposed to unauthorized roles.
8. **Mock actions are simulated**: copy button doesn't copy, “Export receipt” and “Open Assurance Case” just change button text for a moment. Production actions must actually navigate/copy/export under authorization or be explicitly unavailable.
9. **Accessibility not complete:** default drawer is opened full-screen with body overflow hidden and no verified focus trap/return, aria-expanded or aria-pressed; table alternative is good but not sufficient. Use existing HAIEC modal and inspector patterns and preserve ESC/back/URL/focus semantics.

### UI proposal for future UX-P05 session

Header: **Delegated Action Integrity** and scoped chain ID / as-of / read basis. Condensed summary with **authority qualification**, **scope comparison** and **target-effect proof** separate. Flow: agent A → grant/handoff → agent B → operation/tool → provider → readback (branch where multi-hop). **Mismatch/unknown pivot** link. Evidence cards on demand. DAI nine-dimension table with five comparisons, missing dims and source citations. Preserve existing Action Map, graph lenses, runtime observations and technical report paths. A *verified* cross-system chain view is feature-gated until its engineering contract truly ships; same-system witness stays unchanged.

## 2. AI Assurance page — what to adopt

### High-value design patterns (selective reuse)

| DeepSeek element | Value | Existing HAIEC route / owner |
|---|---|---|
| **Consequential first-screen headline + action/target/business meaning** | Answers what HAIEC discovered about this actual system, rather than just listing detectors and controls | UX-P04: existing System Workspace Overview and Assurance Case; source-backed action paths, never model-generated hypothetical consequences presented as detected |
| **Current vs frozen evaluation selector, with explicit as-of time** | Critical to immutable evidence semantics and useful for auditors | Existing exact-evaluation binding, snapshot/current loaders and Assurance Receipts; preserve all evaluations and old deep links |
| **Five separately qualified evidence planes** | Correct conceptual structure | Existing E6.2 coverage in `AssuranceCasePanel` and canonical authority read model; keep separate plane basis and evidence refs |
| **Consequences and changes as adjacent but separate narratives** | Makes drift recognizable without treating it as global risk score | Existing Consequence Delta and evaluation comparison, with scope/analyzer/release comparability, add deep link not another diff engine |
| **Controls summary with drilldown** | Turns catalog/proof into operational meaning | Existing Control Catalog/Proof and E6.2 Operations block; show per-control configured vs target-wired vs monitored vs tested only from qualified join |
| **Delegated actions compact list** | Good entry point to specific chain evidence | Existing DAI/agent-action view; cross-system fully verified edges remain gated |
| **Source health and next eligible action alongside the case** | Removes “what should I do next?” friction | E4 source health, E1 goal availability, My Work and canonical next-action owner |
| **Six jobs as light navigation, not funnel** | Makes broad HAIEC product accessible without six new sidebar destinations | Existing GoalAvailabilityPanel / MCP guide; preserve availability, permissions and unknowns |
| **Provider usage summary with explicit data-source basis** | Shows additional capability without implying telemetry means governance | Existing AI Inventory provider admin API and usage/cost route; UX-P12, show unknown tokens as unavailable; need actual provider-project→system attribution |
| **Common drawer grammar** | Consistency among controls/coverage/usage/DAI detail | Existing inspector + HelpDrawer stays educational; at most one contextual inspector at a time, no drawer stacks |

### Required semantic fixes — do not copy verbatim

1. **Reject the seven-dot scalar evidence ladder:** `FILE_STORED → HUMAN_ATTESTED → TYPED_MAPPING_CONFIRMED → PRODUCER_AUTHENTICATED → DETECTOR_EXECUTED → ASSURANCE_EVALUATED → REPORT_HUMAN_REVIEWED` are *independent provenance/workflow facets*, not an ordered, universal maturity level. `ladder:5` and “highest ceiling” hide mixed sources, even when human review happens before producer verification. This reintroduces the previous rejected DeepSeek mock flaw. Replace with independent, source-scoped coverage/qualification labels, not another universal score.
2. **Avoid “Live state” where only current source projection is known.** Show “Current source view, last refreshed/as-of” and freshness; absence of new evaluation never upgrades old proof. Frozen evaluation selector needs exact evaluationId and per-evaluation source snapshot.
3. **Current vs historical consistency is unproven in static mock.** It hardcodes a “current” assessment and an evaluation from earlier today; actual delta requires two comparable *exact frozen evaluated snapshots* and release/scope comparability. An old evaluation cannot be recomputed with current policies or sources.
4. **The sample states a refund amount “can be issued” as consequence.** Unless code-capability, approved delegation, effective grants, actual endpoint binding and target acceptance are qualified for the relevant operation, use narrower language: “Source-reachable refund creation path; actual permission/effect not established” or appropriate qualified fact. Being allowed by policy ≠ authorized to execute.
5. **Five-plane denominator is not an overall safety grade.** “4/5 established” can contextualize coverage but never imply 80% secure. Requested intent and policy source roles must be sourced correctly, not conflated.
6. **Control sample packs catalog, configuration, deployment and testing into a single `state='executed'`.** Must split catalog applicability, configured/approved, target installed, monitored, tested, target effect. E6.2 system-level Operations context explicitly reports per-control binding `NOT_ESTABLISHED` until a real binding owner exists.
7. **Per-scan detector participation and coverage are mocked.** Static source rules for Prompt/RAG in one engine do not imply that a GitHub App PR pack executed those rules. “47 rules,” “3 undeclared tool paths,” “RAG poisoned” and telemetry sampling claims must come from the exact executed analyzer, producer qualification and frozen scan metadata. U6 internal codes not in new customer copy; use HAIEC Assurance Engine, Assurance Receipts, Evidence Verification.
8. **Cross-system “verified” delegated chains are synthetic.** Render a *candidate* relationship or bounded same-system evidence until issuer-qualified cross-system proof is implemented. Mocking scenario switchers on a real customer Assurance Case risks conflating synthetic and tenant data.
9. **Usage data is hardcoded and possibly over-attributed.** Admin API cost snapshots may not provide real per-system token counts; `tokensKnown=false` must render **unavailable**, not zero. A provider project isn't necessarily a unique AI system. Check time period, source basis, currency and identity before displaying totals. “Sync now” toast claiming queued in ~30 seconds is fake in mock.
10. **Mock controls/events are not connected:** “Re-evaluate”, “Open receipt”, “Run test”, “Sync now” in the sample use drawer/toast behavior without real operations. Production actions should use existing backend permission and CAS workflows, consent and qualified read models, with disabled/unavailable states for unwired operations.
11. **Design is dense for smaller screens.** Keep first viewport to one consequence summary, one *real* attention/next-action queue and a compact evidence basis. Most panels should collapse or move into existing tabs rather than form another mandatory long scroll with five drawers. Responsive, WCAG-oriented type sizes and persistent system/org identity matter.
12. **A static screenshot is not an authenticated browser acceptance test.** Before signing off, verify keyboard, screen reader, mobile, permissions, source freshness, exact basis switching, deep links, and no regressions to existing Overview/Action Map/Controls/Evaluations/Reports.

## 4. Presentation/API/MCP integration gates for page teams

- A shared **read-only presentation adapter** may flatten *existing* canonical per-system/per-evaluation facts into accessible labels, stable deep links and common inspector slots. Do not introduce a parallel evidence or verdict store.
- For each drawer field, record the **actual canonical owner**, org/aiSystemId/evaluation/trace/operation key, selected snapshot/current basis, timestamp, evidence ref and support/qualification state.
- The same fact displayed in web, API and MCP must reconcile; no UI-only inference of authorization or effect. Keep `MCP_TO_SAAS_EVIDENCE_INGESTION_HOLD` until separately cleared.
- The source/controls matrix's fallback inputs (IAM JSON, OTLP export, manual attestation) remain valid *candidate evidence paths* with restricted authority ceiling; not stand-ins for native production protection.
- A reviewer receives an exact human decision packet; a developer sees scanner/producer/provenance; an executive sees consequence and risk/proof boundaries. Role changes **presentation**, not deterministic assessment.
- No main-page UI “fully verified” claim unless every material join is qualified, independent and current for the claim's scope. Missing observations or not wired native target remains UNKNOWN/NOT_ESTABLISHED.
- Never use legacy numeric internal engine/receipt terms in new customer-facing headings or copy. Preserve serialized API and database identifiers for compatibility.

## 5. Acceptance, falsification and final decision

Before adaptation passes: (1) selected AI System's existing tabs, routes and actions inventory; (2) canonical source-to-UI field mapping and error/unknown states; (3) 3 user roles (viewer/approver/operator) and a no-data tenant; (4) actual correct DAI NINE-dimension states on no grant, widened grant, revoked grant and readback absent; (5) evidence plane independence and historical vs current basis; (6) operational controls not-wired/read degraded; (7) consent on runtime test / kill switch and approval CAS; (8) provider usage token-unavailable and source attribution; (9) table/graph parity and accessible focus; (10) production screenshots if an authenticated safe browser session exists, otherwise mark NOT_RUN.

**Outcome:** **ADAPT** visual storytelling, consequence-led hierarchy, change/readiness/next-action grouping, chain pivot, evidence table, and per-topic details; **REJECT** synthetic facts or UI actions presented as real, scalar seven-stage evidence maturity, no-grant=violation, unverified cross-system chain=proven, and replacement of current HAIEC functionality. Both DeepSeek HTML references stay unchanged for side-by-side design inspection.
