## Decision: one page per independent design and delivery session

E6.0–E6.2 fixed data connections and some workflow gaps; the page experiences remain heterogeneous and have not been authenticated-browser-tested. Stop broadly adding panels to multiple unrelated screens in a single sprint. **Each session has one primary route/surface, an exact source/permission/next-action map, designer review, scoped incremental patch, focused checks, responsive/keyboard inspection where safely available, and a matching Common Repo delivery record.** Subsequent pages must use findings from prior sessions without inheriting a new unreviewed global shell.

**Design constraints:** calm, readable, consequential action first, progressively disclosed evidence depth; role-aware presentation, never role-by-UI privilege; no new score, fake completion, new verdict engines or indiscriminate gallery. Do not rename APIs, system IDs, evaluation/receipt identifiers, or change persisted authority/proof. Customer-facing **HAIEC Assurance Engine / Assurance Receipts / Evidence Verification**, never legacy numeric internal names; compatibility remains intact.

**Global interaction contract:** a user can begin from their AI system, their objective, or available evidence; this is one initial surface with three peer choices and local progressive detail. Six independent jobs Discover/Evaluate/Authorize/Monitor/Protect/Verify show **minimum to start, eligible output, stays unknown, permission and next action** using canonical E1/E2 and MCP guide. For details prefer **Why this? → Established → Unknown → Evidence/basis → Next permitted action**; one contextual inspector slot per workspace where useful, no nested drawers or reimplementation of Help Drawer. Confirmations for privileged writes use a separate genuine review/authorization dialog.
