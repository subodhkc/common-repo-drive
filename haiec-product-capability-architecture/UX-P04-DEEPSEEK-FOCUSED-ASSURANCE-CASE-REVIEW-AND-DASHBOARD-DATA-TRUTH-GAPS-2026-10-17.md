## 3. Explicit semantic errors / blocked copy in this mock

1. **Seven-rung maturity ladder is not HAIEC assurance qualification.** The mock's `ladder(count)` uses `i <= count`, incorrectly filling a dot even at zero. Never communicate a required static progression from file upload to full assurance. Existing enforcement rung states are a **different, source-owned operational projection**.
2. **Current vs frozen is a label-only toggle.** Consequence, five planes, controls, chains, recent evaluation and sources remain the same fixture values for both. Real implementation requires separate current read and exact frozen `evaluationId`/`scopeDigest`/qualifying-basis reads, with explicit as-of.
3. **A clicked historical evaluation row always executes `setBasis('evaluation')`** without choosing the clicked record; a row can appear to select a prior evaluation while the header still references the latest. Record-identity binding is a P04 acceptance test.
4. **No latest receipt does not justify fallback.** `openReceiptInspector()` selects first receipt matching system name or global default; this can show the wrong evaluation, wrong system or another scope's receipt. Production must use canonical **exact evaluation receipt binding**, including NO_RECEIPT/REVOKED/old receipt distinction.
5. **No findings ≠ no possible consequences; five planes ≠ fully qualified system.** Mock "No unresolved items", "This system is fully qualified", and "No consequential findings … all reachable paths are either authorized or not established" overstate unseen paths, missing source categories and operational readiness. Preserve scoped absence/unknown.
6. **AWS IAM observer or JSON cannot establish universal per-action EFFECTIVELY_GRANTED** while SCP/resource/session context is unresolved; `AWS IAM export … strengthens EFFECTIVELY_GRANTED` and `Authority first completes … EFFECTIVELY_GRANTED` are unsupported certainty claims. Say "declared/candidate IAM policy facts", qualified limitations.
7. **Absent delegation ≠ confirmed unauthorized action or 9/9 mismatches.** The mock's "Handoff without grant" marks every dimension mismatched and an observed tool outside authority merely because no grant was found. Distinguish authority unverified from actual scope contradiction unless a trusted complete negative authorization basis exists.
8. **Synthetic "KMS signed", native PEP installed, Stripe signed webhook, independent balance readback, provider costs and 47/44/38 executed rule counts are fixtures.** Do not display them as production validation. A collector's OTLP handoff claim alone is not independent authorization/effect proof.
9. **Five evidence planes are not detector coverage.** The mock's plane click launches Detection Coverage and states "click any plane to see which analyzers ran"; provide separate action-plane evidence inspector and exact-run detector analyzer/source coverage inspector.
10. **Facet presentation contradicts itself:** miniature "12 operational facets" has 8 values, and separate control inspector declares eight facets; these are not universal required gates for every HAIEC control. Control applicability varies; control operations include kill-switch, alert threshold/delivery and human operational decisions beyond test replay.
11. **Six jobs are destinations, not generic in-page scroll targets.** The mock maps Discover/Evaluate to the same consequence anchor and Monitor to Sources, implying a job completed simply by scrolling.
12. **Missing mobile basis and navigation and modal/accessibility limitations** require real semantic links, focus restoration, proper dialog focus management, visible basis/as-of, and keyboard/mobile access. Demo persona switch is NOT RBAC.
13. **Do not import JavaScript `innerHTML` UI or hard-coded tool/action links** into production. Preserve React architecture, component isolation and API claims validated per deployed path.
