## 2. Critical newly discovered credential routes — canonical versus legacy

**Preferred canonical owner: `POST /api/keys/create`** (`app/api/keys/create/route.ts`): production NextAuth session; `requireOrganizationAccess` canonical ACTIVE selected organization membership; `isOrganizationAdmin` requires actual organization owner/admin role; superadmin role alone is NOT an organization-membership bypass. This route invokes `createApiKey` with auditable `name`, `isSandbox`, `keyType` and `expiresInDays`, explicit `KEY_PURPOSE_SCOPES['read-only']` = scan:read/report:read/system:read/source:read, `role='viewer'`. Returns plaintext exactly once; audit `api_key_created` (never key plaintext). Corresponding `POST /api/keys/revoke` org-bound owner/admin checks, audit, and `isActive:false`.

**Previously missed legacy superadmin owner: `POST /api/admin/create-api-key`** (`app/api/admin/create-api-key/route.ts`): requires actual session and `isSuperAdmin(session.user.id)`; validates target user's actual active organization membership, but directly `prisma.api_keys.create` with `keyHash`, `encryptedKey:''`, `isActive:true` and `organizationId`. It does **NOT set** `expiresAt`, `scopes`, `role`, `keyType`; schema defaults: `role='viewer'`, `scopes=[]`, `keyType='runtime'`, `expiresAt=null`. Current `effectiveScopes(viewer,[])` conservatively maps to read scopes; however this is **indefinite, legacy-implicit, not explicit least-scope issuance**, and may have different audit properties. It also returns plaintext key and a duplicated Authorization example. **DO NOT use the legacy superadmin endpoint as-is to solve the one-day read-only testing requirement.** Admin API key generator UI currently consumes this legacy route, so preserve backward compatibility or deprecate deliberately if any corrective code is needed.

**MCP issuance:** the deployed 61-tool HAIEC MCP tool registry does NOT contain a key mint/revoke tool; its preflight points to account/dashboard key management. Do not invent `haiec_create_api_key` or issue bearer via a read-only MCP key; doing so would weaken tenant governance. A superadmin role cannot replace authentication.
